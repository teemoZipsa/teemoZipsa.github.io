    🤔 안전한 비밀번호 Q&A
    안전한 비밀번호란 무엇인가요?
    공격자가 추측하거나 자동 대입 공격(Brute Force Attack)으로 찾아내기 어려운 비밀번호입니다. 핵심은 충분한 길이와 예측 불가능성입니다. 미국 표준기술연구소(NIST)의 디지털 신원 지침 SP 800-63B 개정 4판은 비밀번호만으로 로그인하는 경우 최소 15자, 2단계 인증과 함께 쓰는 경우 최소 8자를 요구하고, 대문자·숫자·특수문자를 반드시 섞도록 강제하는 구성 규칙은 두지 않도록 권고합니다. 사람이 규칙에 억지로 맞추다 보면 Password1!처럼 예측하기 쉬운 패턴이 생기기 때문입니다. 이 도구처럼 완전히 무작위로 만든다면 문자 종류를 늘리는 것도 강도를 높이지만, 길이를 늘리는 효과가 더 큽니다.
    강도 표시(비트)는 어떻게 계산하나요?
    선택한 문자 풀의 크기와 길이로 계산한 엔트로피(비트)입니다. 대문자·소문자·숫자와 기본 특수문자 26종을 모두 쓰면 문자 풀은 88종이고, 한 글자마다 log₂88 ≈ 6.46비트가 더해져 16자면 약 103비트가 됩니다. 문자 종류마다 최소 한 글자를 넣도록 보장하면서 줄어드는 조합 수만큼은 빼서 보정합니다. 45비트 미만은 약함, 45~63비트는 보통, 64~79비트는 강함, 80비트 이상은 매우 강함으로 표시합니다. 이 계산은 이 도구처럼 무작위로 만든 비밀번호에만 해당하며, 사람이 직접 지은 비밀번호의 강도를 판정하는 기준은 아닙니다.
    내 비밀번호는 서버에 저장되나요?
    이 도구는 현재 브라우저에서 crypto.getRandomValues()를 사용해 비밀번호를 생성하며 앱 서버로 결과를 전송하거나 저장하지 않습니다. 최근 기록은 페이지 메모리에만 유지되어 새로고침하거나 탭을 닫으면 사라지고, '기록 지우기'로 즉시 비울 수도 있습니다. 다만 기기 보안, 브라우저 확장 프로그램, 클립보드 기록까지 이 페이지가 통제할 수는 없으므로 신뢰할 수 있는 기기에서 사용하고 결과는 비밀번호 관리자에 보관하세요.
    최근 기록에는 어떤 비밀번호가 남나요?
    길이 슬라이더를 움직이거나 옵션을 바꿀 때마다 비밀번호가 새로 만들어지지만, 기록에는 복사했거나 🔄 버튼으로 새로 만든 비밀번호만 최대 10개까지 남습니다. 가입 도중 다른 값을 복사해 버렸을 때 직전 비밀번호로 되돌아가거나, 방금 쓴 비밀번호를 비밀번호 관리자에 저장했는지 확인하는 용도로 활용합니다. 여러 계정에 쓸 비밀번호가 한꺼번에 필요하다면 '여러 개 한 번에 만들기'를 이용하세요. 공용 PC에서는 사용 후 '기록 지우기'를 눌러 주세요.
    몇 자리로 만드는 것이 좋나요?
    비밀번호만으로 로그인하는 계정은 최소 15자를 권장하고, 2단계 인증을 켠 계정도 12자 이상이면 여유가 있습니다. 금융·메일·클라우드처럼 중요한 계정은 16자 이상을 권장합니다. 같은 길이라면 문자 종류가 많을수록 강도가 올라가지만, 길이를 늘리는 쪽이 효과가 더 큽니다. 예를 들어 네 종류를 모두 섞은 8자는 약 50비트이고, 소문자만 쓴 16자는 약 75비트입니다.
    헷갈리는 문자 제외는 언제 쓰나요?
    종이에 적어 전달하는 임시 비밀번호, Wi-Fi 비밀번호처럼 사람이 눈으로 보고 직접 입력해야 할 때 유용합니다. 대문자 I, 소문자 l, 숫자 1, 세로선 |, 대문자 O, 숫자 0, 소문자 o를 빼 두면 글꼴에 따라 비슷해 보이는 문자 때문에 생기는 입력 실수를 줄일 수 있습니다. 문자 풀이 줄어드는 만큼 강도가 약간 낮아지므로 길이를 1~2자 늘리면 충분합니다.
    특수문자 목록은 왜 바꿀 수 있나요?
    일부 사이트는 특정 특수문자만 허용하거나 따옴표·꺾쇠·백슬래시 같은 문자를 거부합니다. '사용할 특수문자' 칸에 해당 사이트가 허용하는 문자만 남기면 가입 단계에서 거절되는 일을 줄일 수 있습니다. 영문자·숫자·한글·공백은 특수문자 칸에 넣을 수 없으며, 입력하면 제외했다는 안내가 표시됩니다. 특수문자를 아예 허용하지 않는 사이트라면 체크를 해제하고 길이를 늘리는 편이 좋습니다.
    비밀번호를 재사용하면 왜 위험한가요?
    한 사이트에서 유출된 비밀번호가 다른 사이트 로그인 시도에 그대로 쓰이는 경우가 많습니다. 이를 크리덴셜 스터핑이라고 부릅니다. 그래서 쇼핑몰, 커뮤니티, 메일, 금융 계정은 서로 다른 비밀번호를 써야 합니다. 생성한 비밀번호는 브라우저나 운영체제의 비밀번호 관리자에 저장하고, 중요한 계정에는 2단계 인증을 함께 켜는 것이 좋습니다.
    생성한 비밀번호는 어디에 저장해야 하나요?
    무작위 비밀번호는 사람이 외우기 어렵기 때문에 안전한 비밀번호 관리자에 저장하는 방식이 현실적입니다. 브라우저 기본 비밀번호 관리자, 운영체제 키체인, 전용 비밀번호 관리 앱 중 하나를 정해 계정별로 다른 비밀번호를 보관하세요. 메모장, 메신저 대화, 이메일 임시보관함처럼 검색되거나 동기화 범위를 알기 어려운 곳에 원문 그대로 저장하는 것은 피하는 편이 좋습니다.
    이 도구가 보장하지 않는 범위는 무엇인가요?
    생성기의 무작위성은 최신 브라우저의 보안 난수 구현을 기준으로 합니다. 이미 감염된 기기, 악성 확장 프로그램, 유출된 클립보드와 사용자가 같은 비밀번호를 다시 쓰는 위험까지 막아주지는 않습니다. 중요한 계정은 서로 다른 긴 비밀번호와 2단계 인증을 함께 사용하세요.
